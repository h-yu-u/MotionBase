# 评审规则

## 根据反馈选修改层

| 用户反馈 | 先检查的位置 | 常见保留项 |
| --- | --- | --- |
| “只换成木刻” | 项目画风选择、风格资产 | 动作、机位、相机投影、画幅、帧率与时长 |
| “起跳提前四帧，落地不变” | 动作源起跳段、落地段和拖尾采样 | 落地帧、落地点、落地后的动作 |
| “落地看着飘” | 落地关键帧、支撑脚、地面参考 | 用户指定的总时长、角色和镜头 |
| “人物太小” | 舞台相机、视角和画幅 | 角色动作及用户指定的背景 |
| “拖尾挡住脸” | 拖尾时段、局部端点、宽度及采样 | 主动作、机位和镜头总长 |

先读实际契约和相关资产源文件，再选择字段。资产未声明地面参考或支撑区间时，说明尚缺什么，避免把目测写成接地检查通过。

## 记录与判断

每条评审记录包含：

- 原始反馈、作品与镜头号，以及基准输入和预览的位置。
- 允许改变、必须保留、涉及的帧段。
- 实际修改字段、资产变体和版本锁的变化。
- 执行命令、退出码、报告与预览位置。
- 自动检查结果、视觉评审结论和待用户判断的具体画面。

“只换画风”的通过条件包含 `compare` 返回 `0`，再加上新预览的视觉确认。

“局部改动作”的通过条件按保留项逐项判断。完整运动对比理应出现局部差异，不能以调大容差掩盖它，也不能把预计的运动变化误判为所有约束都已通过。

保留改动前后的 `.blend`，确保需要复核时可以逐帧重现。对尚未建立的专用检查，记录观察帧号和证据，并明确它是人工评审结论。
