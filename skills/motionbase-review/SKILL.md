# MotionBase 评审

把用户反馈定位到明确镜头和帧区间，保存基准后实施最小修改并提供可复查结果。

## 建立基准

1. 阅读仓库 `AGENTS.md`、作品 brief、`project.json`、`project.lock.json`、目标镜头及最近评审记录；观看当前预览。确认镜头号和实际输入版本，避免用过期预览评审新配置。
2. 阅读 [评审规则](references/review-rules.md)，把反馈拆成“允许改变”和“必须保留”。复用用户已有授权，直接执行范围内的修改。
3. 保存基准镜头、项目配置、锁和预览的版本引用。将改动前后产物放入不同的 `build/review-<序号>/before/` 与 `after/` 目录，保留各自编译 JSON、`.style.json` 和 `.blend`。
4. 若缺少基准 `.blend`，从未改动的输入执行 `compile` 和 `build`；完成后再编辑源输入。锁验证失败时先定位差异。

## 定位责任并修改

- 改画风：编辑作品中的风格选择；保持原镜头、动作与资产选择。风格修改后运行 `lock` 记录新的选择，重新编译。临时试样可用 `compile --style <包ID:风格ID>`，仅选择当前锁已经覆盖的包。
- 改机位：先读取 `contracts/shot-v1.schema.json`。当前 v1 由舞台资产提供相机，不支持镜头级相机覆盖；生成作品专用舞台变体并更新作品引用，避免向镜头 JSON 添加不存在的相机字段。
- 改局部动作：检查动作源和关键帧区间。用户要求“起跳提前四帧、落地时间与位置不变”时，制作作品专用动作变体并修改起跳段，保留落地段，再重新采样相关拖尾；不得把整条片段平移后声称保持落地。
- 改模型、道具或舞台：将本片专用调整保存在作品资产目录；更新作品引用和锁。需要跨作品发布时使用资产包的新版本，避免静默改变其他作品的共享文件。
- 改拖尾或效果：仅调整相关帧区间及契约字段，并在新动作上重新构建。不要在 Skill 中重复实现骨骼绑定、着色或数值校验。

## 检查和比较

按 `compile → check → build → render` 执行，给每轮使用不同的输出目录。编译产物为 `<名称>.json` 和 `<名称>.style.json`，后者通过 `--style` 传给三个旧入口。

若用户要求保留动作、构图和时长，比较改动前后的 Blender 工程：

```bash
python3 -m motionbase compare productions/fox-study/build/review-001/before/010.blend productions/fox-study/build/review-001/after/010.blend --report productions/fox-study/build/review-001/compare.json
```

该命令比较帧率、总帧数、画幅、相机投影以及逐帧相机和骨骼世界变换；退出码 `0` 表示通过，`1` 表示失败。读取具体报告，不以仅有命令输出文件判定通过。不要为消除真实差异随意放大 `--tolerance`。

对有意修改运动的请求，全帧 `compare` 出现差异是预期现象；根据用户保留项检查相应区间及边界帧，并将当前工具不能自动证明的条件明确标为待验收。需要保持落地时，检查落地帧、脚部接触、位置与支撑期的变化；未测量接地规则时不声称自动验证了无滑步。

观看新预览并对照旧版，检查运动连贯性、轮廓、接地和画面可读性。程序一致性通过不能代替视觉评审；视觉满意也不能覆盖契约失败。

## 记录本轮结果

在作品 `reviews/` 下记录反馈、镜头号、基准版本、修改字段、受影响资产及帧段、执行命令、检查结果、预览路径和剩余判断。更新 brief 中已接受的创作决定。

交付新版预览与简洁改动说明，区分已验证的保留项、预期改变和尚未验证的条件。环境缺少 Blender 或 FFmpeg 时，保留可执行输入和准确错误，说明停在哪个步骤。
