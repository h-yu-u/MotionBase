# MotionBase 实现架构

## 交付边界

本次将原始 `motionbase-blender-python.zip` 拆成引擎、共享资产和作品输入。原始设计保存在[架构提案](architecture-proposal.zh-CN.md)。

当前使用 `h-yu-u/MotionBase` 的 `main` 与 `assets` 分支分别维护代码。`main` 检出为 `MotionBase/`，`assets` 检出为同级 `motionbase-assets/`；两个目录分别是可独立版本化的工程。资产分支可以直接迁到新仓，作品只需保持包路径可解析。

| 层 | 目录/模块 | 责任 |
| --- | --- | --- |
| 创作与评审 | `skills/` | 把创作意图变成契约输入、解释预览反馈、保留版本证据 |
| 作品 | `productions/<作品>/` | brief、镜头、风格选择、锁、作品专用变体与评审 |
| 作品编译 | `motionbase/project.py` | 验证锁和兼容性，将 ID 引用降为既有 v1 文件输入 |
| 资产发现 | `motionbase/assets.py` | 校验包清单、限定包内路径、计算文件指纹 |
| 通用契约 | `motionbase/config.py`、`contracts/` | 类型与跨字段校验，公开编辑器可用 schema |
| 执行编排 | `motionbase/cli.py`、`runner.py` | 薄 CLI、子进程、临时目录、编码和结果发布 |
| Blender 执行 | `worker.py`、`look.py`、`trails.py` | 装配集合、绑定动作、材质、拖尾与渲染 |
| 保留项对照 | `comparison.py` | 逐帧运动、相机投影、画幅和时间检查 |
| 共享资产 | 独立资产工程 `packs/fox-cliff/` | 模型、背景、动作、画风、声音、制作源码和素材专属回归 |

CLI、配置、资产发现和作品编译可以在没有 Blender 的 Python 里运行。只有执行或比较时才启动隔离的 Blender 进程。通用测试自己生成小素材；引擎不导入狐面角色的生成代码。

## 数据流

`project.json` 选择资产包和镜头。`project.lock.json` 固定引擎源码版本、项目与镜头输入、资产清单及每个被发布的文件内容。编译器验证这些指纹后读取 ID 镜头，验证角色和 Action 的 `rig_id` 一致，再生成普通 v1 镜头及对应风格 JSON。

渲染器始终消费 `shot.json + style`。旧的显式路径镜头继续直接执行。编译产物中的绝对路径是本机中间结果；项目、包清单和锁使用相对路径，可随两个工作目录一起迁移。

`build` 输出可编辑 `.blend`；`render` 输出 H.264/AAC MP4。相同镜头使用不同风格后，可通过 `compare` 验证运动、相机参数和画幅未变。材质外观和审美质量仍需预览评审。

## 版本与资产更新

包的 `revision` 是人可读版本，SHA-256 固定实际内容，两者同时记录。锁还覆盖风格所引用的材质 `.blend`；材质贴图应由资产作者打包进 `.blend`，未打包的外部依赖不在此版本锁的覆盖范围内。

有意修改共享资产时发布新修订；作品需要主动更新并接受新锁。作品专属动作或机位先建立本地包，通过该作品 `project.json` 引用。代码不会自动修改共享包，也不会在锁过期后静默重新生成。

当前保留两份小型内置画风作为旧命令的兼容入口。独立资产包中的同名风格是新作品的显式输入；使用包 ID 的作品始终读取包文件，不回退到内置副本。

## 已实现与后续

已实现：资产包清单、ID 解析、版本锁、源/资产内容漂移检测、角色动作兼容检查、独立素材工程、作品范例、两个 Skills、旧 v1 兼容、通用运动与构图对照、CLI 安装包与 CI。

继续使用舞台内相机。出现同一舞台的第二种运镜需求时，再增加镜头相机覆盖；当前可用作品专属舞台变体表达。接地检测需要明确的支撑骨、接触区间与地面参考；骨架重定向、多镜头编排与宿主 UI 也不在本次拆分中。
